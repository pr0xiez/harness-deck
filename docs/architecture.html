Architecture

harness-deck

A desktop workspace for running coding-agent CLIs — Claude Code, Codex, Copilot, Gemini, Aider and friends — side by side in a deck of terminal panes. One Electron shell, three isolated layers, and a PTY pipeline connecting real child processes to WebGL-rendered terminals.

01Process topology

Classic three-process Electron split with contextIsolation on and nodeIntegration off. The renderer never touches Node — everything crosses one typed bridge, window.harness, exposed by the preload script. A fourth layer of pure TypeScript (src/shared) is imported by all three via the @shared alias.

02The PTY pipeline

The core data path. Each pane owns one node-pty session in the main process, keyed by pane id; sessions outlive the window, so panes re-attach from a replay buffer instead of restarting.

live sessionor re-attach: created:false + replay buffer

Attention is a main-process timer: every byte of output re-arms a quiet clock; when it expires, pty:quiet flips the pane to waiting and fires a desktop notification if the window is unfocused. Crash restarts are renderer policy — cap of 3, backoff 1 s / 5 s / 15 s, reset after a 60 s healthy run.

03State & persistence

One zustand store is the source of truth in the renderer; the main process owns the disk. Everything is plain JSON under Electron's userData directory, written atomically (.tmp → rename, with a .bak fallback on corrupt reads).

useDeck changesworkspaces · panes · settings
→
serialize()strips transient pane state
→
debounce 400 msskip if snapshot unchanged
→

→

On boot, hydrate() merges saved settings over defaults (so old files gain new fields), resets panes to idle, and scrollback logs are pruned against the pane ids that survived.

04Voice dictation path

Speech-to-prompt for the panes. Audio never touches disk, and API keys never enter the renderer. A silence gate refuses to transcribe room tone — nothing is sent unless ≥150 ms of voiced audio clears a threshold derived from the measured noise floor.

MediaRecorderwebm/opus · RMS meter · auto-stop on silence
→
heardSomething()the gate: voiced ≥ 150 ms & peak > noise floor × 5
→
voice:transcribeWAV re-encode when the provider needs it
→
provider APIOpenAI / Groq / OpenRouter / custom · key via safeStorage
→
deliver()one-line transcript → focused pane or broadcast box

05Build, test & release loop

electron-vite bundles three targets (main, preload, renderer) out of one repo; electron-builder packages them; a script pipeline publishes to GitHub Releases, which the in-app updater watches.

Ship

→
electron-builderNSIS/zip · dmg (arm64+x64) · AppImage/deb; node-pty kept outside asar
→
publish-release.mjsGitHub REST · v* tag → draft release
→

Verify

typechecktwo tsconfigs: node + web
→
vitest · node projectmain/preload/shared, no electron imports
→
vitest · renderer projectjsdom + Testing Library, typed window.harness stub
→
smokeboots the real built app, asserts panes spawn/restart/persist

CI runs the same sequence on a Windows runner and a self-hosted mac (.github/workflows/build.yml).

one runtime dependency

Everything ships as devDependencies except @lydell/node-pty — the only native module, unpacked from the asar for its prebuilds.

no telemetry

The entire codebase makes exactly three kinds of outbound requests: the update feed, the installer download, and voice transcription.

panes survive the window

PTY sessions live in the main process; on macOS, closing the window leaves agents running and panes re-attach from the replay buffer.
