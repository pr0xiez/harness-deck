What T3 Code got right — and how to steal it without the threads

A teardown of pingdotgg/t3code (repo clone + web sweep), distilled into six features re-landed on Harness Deck's axes: the pane, the workspace, the worktree. No conversation threads, no output parsing — the deck stays a place where you watch real terminals.

The shape of the thing

One correction to the mental model first: T3 Code is not a chat wrapper. It runs real server-owned PTYs rendered with Ghostty's VT engine on every surface, and the terminal is a first-class panel. What makes it thread-based is deeper: the atomic unit of work is a conversation. A thread owns a branch, a worktree, a permission mode, and a parsed, normalized event stream produced by per-provider adapters — a 3,951-line Claude SDK adapter, a 47k-line generated Codex client, a full ACP implementation. That buys them first-class approvals and plan mode; it costs them an adapter treadmill, a provider locked mid-thread, and field reports of ~3× wall-clock overhead vs the raw CLI.

Harness Deck's identity is the opposite bet: the unit is a process in a real PTY, output is shown rather than parsed, and the only universal signal is timing (the quiet timer) plus what the terminal already emits (the bell, the OSC title). Every borrow below honors that bet.

The translation rule

Steal the semantics, keep the terminal. Where T3 Code attaches a behavior to a thread, attach it to a pane, a workspace, or a worktree. Where they parse provider events to know what happened, show the raw tail and let the user's eyes parse it. Where they run a hidden RPC, run a visible command in a real pane.

What they actually got right

One runtime boundary → every surface free

The server owns every process, terminal, and git op; clients own nothing. Web, desktop, phone, and remote all came from one decision. Remoteness is expressed at the connection layer, never by splitting the runtime.

AGENTS.md
F1

The waiting queue

Size S–M renderer + small main

Borrowed: the thread inbox — settle / snooze / raised-hand wake · Kept: no parsing; the tail of the terminal is the preview.

Attention routing answers that a pane wants you. It doesn't answer which one first, why, or can it wait — with six panes, Ctrl+Shift+J is a blind jump. T3 Code's answer is precomputed flags (hasPendingApprovals, hasPendingUserInput) — which requires parsing. The deck's answer: show the last few lines of each waiting pane's buffer. For an agent at an approval gate, that tail is the question it's asking. pty:transcript already exists; strip ANSI, keep three lines.

Add the inbox verbs, all on the pane, all reversible: acknowledge (seen it — drop it from the badge until it next goes quiet), snooze (until next quiet, or for an hour), mute (this build pane never counts). And the one genuinely free upgrade: the terminal bell is already tracked per pane, and Claude Code rings it at permission prompts — a bell wakes a snoozed pane immediately. That's T3 Code's raised-hand override, reconstructed from a 150-year-old terminal signal instead of an SDK.

  • State: Pane gains attentionMuted?: boolean (persisted), snoozedUntil?: number | 'next-quiet' and acked?: boolean (transient); waitingSince kept in the renderer when status flips to waiting.
  • Tail: pty:transcript (exists) → strip ANSI (the HD-8 stripper) → last 3 non-empty lines, fetched when the queue opens and when a visible row's pane re-quiets.
  • Surfaces: new WaitingQueue.tsx overlay on Ctrl+Shift+U + palette; sidebar badge counts exclude muted/acked/snoozed; Ctrl+Shift+J now walks oldest-first and skips snoozed panes.
  • Bell override: in the store's bell handler, a snoozed pane with a fresh bell clears its snooze and re-enters the queue flagged woke.
F2

Ship & resolve

Size M compare view + git.ts

Borrowed: one-button commit → push → PR · Kept: the commands run in a visible pane, and git still lives in a terminal.

T3 Code's marketing line — no terminal dance required — names a real cost: after Compare says pane B won, landing B's branch is six commands typed by hand, times N worktrees. The deck's translation isn't a hidden RPC; it's a Ship dialog that composes the exact command line and runs it in a one-off pane in that worktree. You watch it happen; failures surface as scrollback, not toast mysteries. gh/glab are detected with the same findExecutable machinery profiles already use, and the optional commit-message flourish borrows their best trick on your terms: pipe the diff through claude -p — the subscription you already have, no side key.

Then the part T3 Code structurally cannot have, because it has no side-by-side at all: Resolve. A comparison of three worktrees wants a verdict — ship the winner, then remove the losers' worktrees and branches in one confirmed sweep instead of three close-pane dialogs.

  • Entry points: a Ship… ghost button in each compare column header and in the worktree pane's header menu; Resolve… in the Compare header when ≥2 worktree panes exist.
  • Execution: a transient pane spawned with the composed line via the existing viaShell path — no new git plumbing beyond gh/glab detection; Compare's read-only philosophy survives because Compare still only reads.
  • Cleanup: Resolve batches the existing close-worktree-pane flow (confirm → git worktree remove → git branch -d), reusing its dirty-tree warning.
F3

Worktree setup hook + deck actions

Size S–M store + toolbar

Borrowed: t3.json scripts, runOnWorktreeCreate, script keybindings · Kept: output lands in a pane, not a log drawer.

The sharpest practical idea in t3.json: a fresh worktree is a broken worktree until deps install. Hand a task to three agents in three worktrees today and all three burn their first minutes discovering there's no node_modules. Fix: a per-workspace setup command (npm ci, pnpm install) that runs in the pane, before the agent starts, by wrapping the spawn as setup && exec <agent> through the existing viaShell path. You watch the install scroll by, then the agent takes over — same pane, no hidden phase. Templates carry it, so a template that fans out worktrees finally works end-to-end.

Its sibling: deck actions — a few named commands per workspace (tests, typecheck, dev) rendered as toolbar chips and palette entries. An action opens a fresh shell pane in the workspace folder (or a chosen worktree) and runs there. This is the praised "custom UI buttons" feature of theirs, minus any custom UI runtime: an action is just a pane you didn't have to type into.

  • State: Workspace gains setupCommand?: string and actions?: {label, command}[]; both copied into WorkspaceTemplate.
  • Spawn: worktree panes with a setup command become viaShell panes running <setup> && exec <agent argv> — restart re-runs setup, which is correct (idempotent installs are the norm).
  • Chips: overflow past ~4 actions collapses into a dropdown; every action is also a palette command.
F4

Quiet checkpoints

Size M git.ts + compare

Borrowed: per-turn hidden-ref checkpoints · Kept: the "turn" is the quiet timer — the same provider-agnostic signal attention already trusts.

T3 Code brackets every turn with a hidden git ref, which makes "what did the agent just do" and "undo that" answerable. Their turn boundary comes from parsed provider events. The deck already has a turn boundary it believes in: the moment a worktree pane falls quiet — the same event that refreshes the repo chip, on the observation that an agent going quiet has usually just stopped writing files. On that event, snapshot the tree into refs/hd/<pane>/<n> (temp index + write-tree + commit-tree — the working tree and the user's index are never touched, and git status never shows it). A week of bursts costs kilobytes and vanishes with the worktree.

Payoff in Compare: each column's baseline becomes a dropdown — since branch point, or any burst — so you can read what changed in the last burst alone instead of re-reading the whole diff. And a guarded restore to burst N gives every harness a code-level undo, whether or not the CLI has its own rewind. Conversation state stays the CLI's own business (claude --resume exists); the deck only promises the tree.

  • Capture: on pty:quiet {quiet: true} for worktree panes with changes: GIT_INDEX_FILE=<tmp> git add -A → write-tree → commit-tree → update-ref refs/hd/<paneId>/<n>. Skip if the tree hash didn't change; keep the last 20 refs.
  • Read: DiffRequest gains base?: string; the column dropdown lists refs with cached stat totals.
  • Restore: git restore --source=<ref> --worktree -- . behind the same warn-on-dirty confirm as worktree removal; refs deleted with the worktree.
F5

Selection → prompt

Size S renderer only

Borrowed: terminal-lines-as-context chips · Kept: it's just text into the broadcast box — no chip runtime, no context protocol.

The most quietly excellent T3 Code interaction: select output, and it becomes prompt context. The deck's version is one shortcut: select lines in any pane — a stack trace in the shell pane, a failing assertion in the dev-server pane — hit Ctrl+Shift+E, and the broadcast bar opens with the selection appended as a fenced block, agent panes pre-targeted. Type "fix this" and send. It replaces the select-copy-open-broadcast-paste-describe shuffle with point-and-say, and it composes with everything broadcast already has: targets, history, snippets, dictation.

F6

Deck Remote

Size L · phased new main module

Borrowed: one execution boundary, phone-first attention · Kept: the phone shows the same PTYs; nothing forks, nothing tunnels, no accounts.

The feature Theo daily-drives (it has changed how I code) and the one their architecture earned: because the server owns everything, any device is a client. The deck is closer to this than it looks — processes already live in the main process, addressed by pane id, with replay buffers; the renderer is already a thin client over a bridge. Deck Remote adds a second, deliberately smaller client: an opt-in local HTTP server (loopback by default, LAN by choice) serving one self-contained page — the waiting queue, pane list, and a live read-only terminal view, paired by QR with a bearer token.

What this is for is not coding from a beach. It's F1's queue in your pocket: three agents grinding, you make coffee, the phone shows worker — waiting 2m with the approval prompt as its tail; phase 2 lets you type 1↵ back. Where T3 Code built Cloudflare Workers, DPoP, and native apps, the deck ships a page and a doc section titled "put it on your tailnet" — encryption and reachability are Tailscale's job, not new infra. Notably, their remote story is what makes their missing desktop notifications survivable; the deck gets to have both.

  • R1 — glance: HTTP + SSE from the main process (zero new runtime deps); serves one bundled page; state = workspaces/panes/status/waiting + terminal replay & live bytes, read-only. QR in Settings encodes http://<addr>:<port>/#<token>; token rotates on disable.
  • R2 — hands: input POSTs gated by a per-device "allow typing" toggle; queue verbs (ack/snooze) and the broadcast box join.
  • R3 — reach: nothing to build — document Tailscale Serve; revisit a ws dependency only if SSE throughput ever hurts.
  • Honesty box: plain HTTP on a LAN is readable by the LAN — say so in Settings; loopback-only default, LAN opt-in, read-only default, no tunnel service ever.

Quick wins

  • Unified/split toggle in Compare's full-diff mode — their diff viewer's one clearly-nicer surface. (S)
  • Deck-wide search: DeckSearch currently scopes to the active workspace; a flag to sweep all mounted workspaces — their palette searches everything, and it reads as magic. (S)
  • Launcher variants: saved launchers already carry env — add a "duplicate as variant" affordance with hints for CLAUDE_CONFIG_DIR (work/personal accounts) and model-pinning vars. Their named provider instances, for free. (S)
  • hd . — a tiny CLI shim that opens/focuses the workspace for the current folder; their t3code . bridge, and the cheapest onboarding moment there is. (S)
  • Editable keybindings (keybindings.json + conflict listing in Help) — theirs ships when-clauses and a conflict UI; a flat remap file is 80% of the value. (M)
  • Adopt their principle verbatim in next-features.md: a one-way door is a bug — F1's verbs all obey it. (free)

Leave on the table

  • The thread model itself — unit-of-work = conversation requires parsing everything; the cost shows up as a 4k-line adapter per provider, provider locked mid-thread, and the 3× overhead report. The deck's whole bet is that the TUI is already the good UI.
  • Per-provider SDK adapters — the treadmill the timing-only stance exists to avoid; every borrow above works on bytes, timing, and git.
  • The embedded browser/preview product — genuinely impressive (port scanning, agent-driven clicks, recordings), and a whole second product to maintain. The user's browser is one Cmd+Tab away.
  • Managed tunnel infrastructure — Workers, Postgres, DPoP, and still no E2E encryption. "Use your tailnet" is a doc section, not a service.
  • Native mobile apps — two app stores of upkeep to render a terminal; Deck Remote's one page serves the same need at deck scale.

Build order

F-numbers are the recommended sequence, cheapest-leverage first: F1 deepens the feature that already distinguishes the deck and is mostly renderer work; F2 + F3 complete the fan-out story end-to-end (setup → broadcast → compare → ship → resolve); F4 rides the quiet event that F1 just made more trustworthy; F5 is an afternoon; F6 is the horizon feature and deserves its own wave once the queue it would serve exists.
